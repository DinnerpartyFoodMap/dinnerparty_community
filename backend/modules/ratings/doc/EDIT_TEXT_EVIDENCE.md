# 编辑评论与文本证据

## 已实现行为

- 地点编辑实际生效时，将描述里新增的文字作为评论绑定修改人：改前 123、改后 123456 只记 456；Markdown 按纯文本比较，几段新增之间用「 … 」连接。评论正文与文本证据是同一段文字。只改店名、分类、人均、图片、位置，或只删减描述的编辑不生成评论，完整前后状态仍在 `PlaceRevision`。规则在 `modules/places/services/placeEditDiff.js`，Web 预览 `frontend/src/places/editEvidence.js` 与 iOS 原生表单各有一份同规则实现（前端 `test-edit-evidence` 与后端对照）。少于 4 个字的公共片段夹在新增之间、或旁边旧文字被删时视为巧合并入新增（如「早茶」改成「出品稳定的茶楼……」记整句，不拆成「出品稳定的 … 楼」）。旧格式（「描述：旧 → 新」）记录用 `npm run edit-comments:rewrite` 预览/改写，见 [脚本说明](../../../scripts/doc/README.md)。审核申请归申请人，执行管理员另记；审核前不公开评论或补评分。
- 旧地点现有描述按当前创建者建立一份归属记录；创建新地点时的描述也进入同一链路。脚本更换创建者时，同事务转移这份描述、关联评论和创建者对应的评分（包括创建后手动改过的分）；新创建者已评价则保留其评分并去掉旧附带评分。其他用户的独立编辑和个人评价保留原归属，不新增票数，派生文本期限不续期。
- 未评价者提交编辑须选择四档评分，或选择“仅纠错，没有实际体验”。已有评分（包括历史默认评分）直接保留。补评分、修改和评论同事务；审核时不覆盖新评分或复活提交申请后撤回的评分。无实际修改、重复保存及重复审批不增加评论或票数。
- Web 和 iOS 原生编辑表单均有评分选择、纠错例外及“修改记录预览”，提示生效后按修改人保存且仅管理员可查看。记录显示作者昵称和时间。两个评分的展示方式继续沿用现有规则。
- 仅管理员的地图“更多”和iOS详情显示“修改记录”入口，只读展示描述及生效修改，未开启自由评论发布。读取接口要求登录及`manage_comments`权限，不带`kind=edit`的旧请求同样校验；创建者和普通用户不能查看，权限撤销后也拒绝读取。退出、切换账号或地点时清空面板和过期请求结果。编辑证据仅取新增字符片段；历史创建者绑定按用户指定的归属规则使用现有描述全文。每人每店仍只有一票，多次编辑取有界最大证据系数；不累计票数。

## LLM 与权重

`ratingContentJudge.js` 使用已在P103专项实验运行的content-v2固定提示词，复用DeepSeek生成式API，分别输出文本极性、具体程度、正面支持、负面支持、负面严重度、模板程度、置信度及原文片段。API不接收星级、用户身份或全店均分。原 `ratingTextJudge.js` 保留用于复现初始实验。4B embedding与生成式判断职责不同，本次不替换embedding或模型包。

后台每15秒最多评估8条，单次调用最长45秒；最多三次失败后停止自动重试。相同文本、提示词和模型复用缓存。缺文、无体验、低置信度、失败或证据已失效时系数为1。请求链路不等待LLM；影子指标更新不触发全站评分汇总重建。`GET /places/:id/edit-context`仅查询本人是否已评价，不调用数值模型。

候选系数为 `1 + 0.25 × 与本人评分方向对应的文本支持 × (1−模板程度) × confidence`，范围1..1.25；正面和负面均可提供支持，详细不等于严重，模板判断不代表造假判定。私有服务通过 `text_evidence_policy=bounded-text-evidence-v2` 和 `text_evidence_mode=shadow|active` 验证、回显，并在店铺聚合中实际计算，兼容v1旧协议。严重度单独记录，未凭直觉改成评分处罚。实际人数、票数、默认评分和P102保护保持。

已有画像模型对生成评论只读取有效、同评分版本的作者贡献片段或创建者绑定描述，不读取带有旧文/删除内容的整个修改差异；新增的简短具体片段也能进入提取。真实来源变化会刷新画像，权重影子计算本身不替换产品评分。冻结树模型和其评分者拟合公式未重训。

**默认active，作为用户指定的公共质量证据规则。** 公共分的目标是估计质量，未来大众均分的预测误差仅作代理诊断；用户明确允许MSE提升不大时采用产品规则。系数仍被限制在1..1.25，无有效文字为1，不补造投票或降低避雷保护。此选择不代表研究门槛已通过，也不证明真实质量准确度已提高。`shadow`返回原分并计算候选分，`off`停止评估；active也返回内部基线差值用于监测。“预计你会给”仍是独立个人评分预测，首选树和风险树没有重训或宣称新命中提升。

## 实验记录（2026-11-05）

研究预处理曾把Pandas空值变成字符串`nan`，已登记更正并重新计算；旧输入和旧结果保留追溯，以下为修复后的数值。真实空文本不会被当作模板，不请求LLM、不直接降权。生产JavaScript无Pandas转换路径，并已增加null/undefined/NaN及真实空描述回归。

仅使用 `research/rating-confidence` 内 Google 开发数据；未使用服务端数据库快照。384家店，截止2018-10-01，之后至2019-04-01的独立用户评分作为目标；至少20条未来评价。1..30条历史评价的研究店按预先登记规则抽样，偏重历史负面多数店，不能外推全体商户。

这些店共有6527条历史评价，2265条没有文本；随机抽样涉及3695条，其中1249条为空。非空文本2446条中，2334条有有效content-v2结构化输出，其他回退基础系数。使用0/17/42三个固定种子抽1/2/3/5条；另有前缀对照。每个种子/数量均先移除研究店未抽中的评价，再拟合完整评分者、类别及店铺图，避免隐藏评价泄漏。

按店隔离校准/评估：1条时选出模板降权，评估MSE0.383650→0.383027（约−0.16%），差值95%区间[-0.002074,+0.000152]跨零；2/3/5条仍选基线。评估低分店仅6家，不足安全门槛。归一化n=1严格等于基线。不同n队列大小不同，固定共同队列、逐种子结果保存在JSON；同店重复种子不是独立复现。

分组将原生中性3星单独列出，避免混入好评。好评中，真实无文本991条、模板325条、长篇具体188条，单条评分对未来均分的MSE分别0.345207/0.330589/0.307451。方向上长篇具体较好，但店内对比长篇减空文本的差值区间[-0.083003,+0.016111]、减模板[-0.111383,+0.009952]均跨零。详细评价可能有价值，不能由此推出固定增权一定优于已有收缩。差评模板仅7条，数据不足以判断模板负评可靠性。文字严重度也不等于与未来大众均分一致。

同一组17家验证店的详细好评单条样本：原始评分MSE0.427774、全站先验0.198032、当前类别收缩0.128499、再加文本支持0.127893，点估计改善约0.47%，区间跨零。当前算法已经比只信详细评分或全站先验更准；不能将整体固定增权无收益解读为详细好评无价值。该诊断见`p103-shrinkage.json`。

最终依据为被仓库忽略的research目录中`results/round12/p103-corrected.json` / `p103-corrected.md`；更正登记为`p103-null-correction.json`。旧`p103-results.md`及其原始JSON仅保留审计。没有盲审人工可靠性标签，不宣称LLM已识别评分随意程度，也未计算首选命中提升。

后续P104按用户要求补MAE/RMSE/signed Bias/Spearman，并建立成熟目标：384家店，历史215～3148条，独立未来101～1154条，目标均分95%区间半宽≤0.15原生分。3条输入时，评估基线四项为0.312984/0.468114/−0.228074/0.454861；文本支持增权为0.315720/0.474719/−0.231449/0.456243。存在误差与排序取舍，没有宣称统一提升。该高精度评估队列缺少真正低均分店，不能作为坏店/卫生风险验证。完整记录为`p104-results.md`和`p104-mature.json`。公共质量政策的启用依据是用户明确的用途要求，登记在`p104-quality-amendment.json`。

## 期限与研究导出

派生证据最长90天，评分版本变化、评论删除、用户/地点删除后失效；旧文本不得通过再次导出延长寿命。修改记录本身按现有内容规则保留，仅管理员可读取。研究包新增去标识的 `text_evidence`，仅包含当时具备研究授权且仍在期限内的文本/指标；撤回授权立即使相应研究包失效，删除评论也使相关包失效并排队清理。

旧地点描述在初始化时按用户指定规则绑定当前创建者，作为当前观察而非补造过去行为；不增加评分或到店事实。独立历史编辑仍只回填作者及前后状态可确认的记录。转移归属使原研究授权失效，不把旧授权或旧时间伪装成新作者的历史行为。
已经删除的编辑评论会保留删除标记，后续回填不会重新发布。
