# 角色观察屋

观察屋是小伙伴（[皮肤与角色](../../skins/doc/README.md#角色与远程皮肤兑换)）的一天：屋里的日常、出门去地图上的店吃饭、和别的住民的小伙伴拼桌或隔空聊天。时间线里的句子全部来自本模块的固定语料，运行时不生成文字。打卡只给小伙伴加饱食度，不进时间线。

目前只有语料和语料校验。时间线的生成、每日排程、熟悉度和接口还没有实现，实现时把行为、接口和测试补到这里。

## 语料

`corpus/` 下的文件：

| 文件 | 内容 |
| --- | --- |
| `rules.json` | 字数上限和写作禁区，校验读这一份；说明见 [语料写作规范](CORPUS.md) |
| `tags.json` | 30 个性格标签（四组）、互斥对、哪几个标签从口味六轴和作息推断 |
| `situations/*.json` | 情境：屋里的（`home.*`）和出门的各步（`outing.*`）。一个情境有几种做法，按小伙伴的标签和问答选一种 |
| `quirks.json` | 小习惯：每个小习惯挂在两三个情境上，带自己的句子，有这个小习惯的小伙伴偶尔用它替换当次的做法 |
| `scripts/*.json` | 剧本：拼桌（`table.*`）、隔空（`remote.*`）、熟悉度升级（`bond.*`），两只小伙伴的对手戏，2 到 4 条 |

### 情境的字段

| 字段 | 说明 |
| --- | --- |
| `scene` / `step` | `home` 屋里；`outing` 出门，`step` 为 `pick` 选店、`leave` 出门、`arrive` 进店、`order` 点单、`wait` 等、`serve` 上桌、`eat` 吃、`spicy` 吃到辣的、`full` 吃撑、`pay` 结账、`back` 回家 |
| `axis` | 只有 `outing.eat-*` 有：店的六类餐饮（`homestyle` 等，同 `preferences/services/tasteAxes.js`）；`outing.eat` 是店没有类别时用的 |
| `axes` | 情境或做法只在这几类店出现（比如吃撑不会发生在饮品店） |
| `anchor` | `wake` 起床、`bedtime` 睡前、`sleep` 睡着，放在一天固定的位置 |
| `window` | 可以发生的时段，当天的分钟数，可以写到 1800（次日 06:00）；做法也可以有自己的 `window`（“十点就关了灯”只在 21:30 到 22:30） |
| `minutes` | 时长；句子自己说了多久的做法（“睡了四十分钟”）用做法上的 `minutes` |
| `when` / `chance` / `days` | `explore` 只在第一次去的店、`spicy` 只在辣的店；出现概率；`weekend` 只在周末 |
| `quiz` / `ask` | 问答的序号（1 到 20，前 6 道在入住时问）和题面；选项就是这个情境的做法 |
| `icon` | “正在……”旁的图标，做法可以覆盖 |
| 做法的 `fits` | 适合的标签，最多 2 个；每个情境正好一种不挑标签的普通做法 |
| 做法的 `say` / `rare` | 一句话那格可以换成口头禅；稀有，抽到时标星 |

占位符：情境和小习惯里 `{a}` 是这只小伙伴，出门的句子可以用 `{place}`（店名）；剧本里 `{x}`、`{y}` 是两只小伙伴，拼桌剧本可以用 `{place}`。剧本在两位主人的时间线里显示同一段文字，写的都是名字，所以不用 `{a}`。

### 剧本的字段

`bond` 是适用的熟悉度范围（0 生面孔、1 点头之交、2 饭搭子、3 老饭友），升级剧情用 `level`。`x`、`y` 是两个位置各自适合的标签，挑剧本时按标签决定谁演哪一边。拼桌剧本可以用 `axis` 限定店的类别。每段正好一条 `star`，是这段的名场面。

两只小伙伴属于两位不同的住民，剧本只写朋友之间的分寸：不写恋爱和身体接触，不评论外表（2026-11-19 定）。

## 语料的来历

第一批语料（2026-11-19）由模型起草，维护者逐条复核修改后上线。它是固定的产品文案，不标「AI 生成」，条款第九节也不另加说明（2026-11-16、11-19 定）。这和“模型写的字到了用户面前要标”的规则（生成的分享帖、模型整理的日记）不同，别当成漏标补上。

## 改语料

直接改 `corpus/` 下的 JSON，然后在 backend 下跑：

```bash
npm run test:rooms
```

`services/roomCorpus.js` 的 `validateCorpus` 会检查每一句的字数、占位符、禁用词，以及成批的比例（有一句话的做法 30% 到 60%、有细节的 60% 到 90%、同样开头的不超过 15%、每个标签至少用到 3 次、06:00 到 24:00 每个小时至少 6 个屋里情境可用）。有错就失败；`node tests/rooms/test_room_corpus.js --warnings` 另外列出只提示的问题（开头用字相同、近似重复）。`loadCorpus().version` 是全部语料文件的哈希，生成过的时间线记下它，改语料不改历史。

测试用例见 [TEST_CASES.md](TEST_CASES.md)。
