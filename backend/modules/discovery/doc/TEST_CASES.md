# 发现文字测试案例库

遵循 [执行协议](../../../doc/TESTING.md)。入口 `npm run test:search`（关键词回归、烟测、标签和结构化搜索）、`npm run test:random` 和 `npm run test:ai-clients`。用私有数值服务的 `scripts/run_backend_tests.js` 启动搜索回归所需的本地服务。模型与向量接口使用替身。

### DSC-C01 先联合排序再截断（2566978）

前置：数量超过 limit 的远处名称匹配，另有较旧但中心附近的分类匹配。操作：用有效 center 搜索分类词，设置较小 limit。预期：附近直接分类匹配进入结果，不因 SQL 先截断被遗漏；/search 与 /search/fast 都传递 center 并返回同序数组。

### DSC-C02 精确名称与语义底线

前置：完整名称匹配、附近仅描述含词、远处分类含词，含避雷精确名称。操作：搜索店名与分类词。预期：精确名称最高优先，用户能找到明确要找的避雷店；仅描述匹配不因近距离挤掉直接分类匹配。

### DSC-C03 归一化与拆词

前置：全半角拉丁文字、标点不同名称、词分别出现在名称/分类/描述中。操作：输入全半角、大小写、逗号分词、% 和 _；缺一个词再查。预期：字面规则一致，所有词均需匹配，通配符输入不会扩大召回；连续中文不假定自动分词。

### DSC-C04 避雷语义

前置：低分无标签、高分旧标签、无评分避雷标签及普通地点。操作：普通查询、独立“避雷 火锅”、连续“避雷火锅”。预期：普通查询降序排列避雷但不删除；独立词触发共享规则筛选；连续词按普通字面匹配；2.5 边界与封禁评分排除一致。

### DSC-C05 非法中心与稳定平局

前置：无坐标、非法坐标、合法 0 坐标；相同文字分与创建时间、不同 ID；旧日期。操作：无中心、非法中心、合法中心分别查询并重复。预期：非法位置不得获距离奖励；同输入顺序确定；日期按显式规则解析，不能用宿主时区决定新旧。

### DSC-C06 AI 不可用

前置：禁用模型密钥或本机上游替身返回错误。操作：独立请求关键词和 AI 接口。预期：基础搜索成功；AI 返回 503 unavailable 的既有结构，不捏造推荐；模型返回值需通过本地地点与格式校验。进一步边界入口 test:ai-clients。

### DSC-C07 随机边界与概率

前置：候选分别在 5km 内、边界、外；含无效坐标与避雷；完整池 4 和 5 两组；排除最近两家。操作：固定随机数或统计抽样；有/无兼容画像分别抽取。预期：完整池不足 5 返回空，再排除历史；基础概率和混合公式正确，保留探索概率；缺向量回基础分布，查询失败不能伪装空结果；响应不暴露用户向量。

### DSC-C08 规模与顺路失败边界（待自动化，DSC-01 / DSC-02）

生成可复现的大候选集，记录 P50/P95、候选数和峰值内存，验证排序等价后才讨论索引。顺路另测非法路径、重复点、极短路径、半径边界和避雷过滤；不得把随机推荐距离测试当作顺路覆盖。

### DSC-C09 推荐语只由模板和原文摘录组成（已有自动化）

前置：模板文件；店铺介绍含 Markdown 的地点；上游替身按需返回逐字摘录、改写过的摘录或空摘录。操作：校验模板文件与几种错误模板；对摘录做核对；用同一原话连续搜索。预期：模板文件通过检查，未加方括号的可选占位符、嵌套方括号、未知占位符和没写店名的无摘录模板被报出（有摘录的模板可以不写店名）；标签去掉“其他”“避雷”“待探索”和重复的，最多取三个用顿号连起来，只剩这几种标签时句子里不提标签；逐字摘录（去掉首尾引号和标点后）被引用进推荐语，改写、跨段拼接、少于 4 字或等于店名的摘录被丢弃并改用无摘录模板，模型措辞不出现在推荐语里；审核提示词只要 `evidence` 不要 `reason`，模型看到的是去掉 Markdown 的纯文字；`reason_source` 恒为 `template`；同一原话结果稳定，同一次搜索的几张卡句式不同。入口：test_search_smoke.js 与 test_ai_clients.js。

### DSC-C10 AI 搜索的候选范围与审核门槛（已有自动化）

前置：地图中心附近一家面馆，北京有多家向量更相似的地点，另有不同距离、价格、可见性和标签的候选。操作：用假客户端生成无 `core` 的条件并触发向量兜底。预期：半径内通过硬筛的面馆进入审核。向量补入数量受限，有结构化候选时不重复。向量不可用时仍可使用结构化结果。入口：`test_search_smoke.js`、`test_ai_clients.js`、`test_structured_search.js`。

### DSC-C11 顺路吃起终点名不剩百分号编码（已有自动化）

前置：落地页 `schema` 里的 App 链接，起点名编码两层、终点名编码一层；`uri.amap.com/navigation` 的 `from` 名字编码三层；名字里有单独的 `%`。操作：`parseAmapRouteUrl`。预期：起终点名都是中文原文（「起点 A」「终点」「起」），单独的 `%` 原样保留（「100%」）。入口：test_taste_axes.js 第 10 段。

### DSC-C12 档案版本与重试

前置为公开地点、隐藏地点和内容哈希仍匹配的旧档案。用假服务模拟取不到版本、整批不可用、模型输出截断和单条无效。预期为跳过无版本的轮次，按批退避，截断时拆半，单条重试耗尽后等待内容或版本变化。失败保留旧档案，地点编辑期间返回的旧结果应丢弃。入口为 `test_structured_search.js`。

### DSC-C13 AI 搜索服务集成

用假服务验证编译与建池并行、向量补充只使用允许的 ID、审核分批及部分失败降级、卡片排序失败时的回退。编译或召回不可用时接口返回 503。HTTP 保留 `filter`，条件与命中详情只在内部诊断模式返回。入口为 `test_structured_search.js`，算法用例见私有服务文档。
