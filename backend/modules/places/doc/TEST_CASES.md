# 地点文字测试案例库

遵循 [执行协议](../../../doc/TESTING.md)。

### PLC-C01 多入口添加（已有自动化：test:qq-bot / test:ratings / test:journey-publication）

前置：临时库、用户、可用分类、假通知目标。操作：网页路由、Bot 确认、日记公开提交各创建一个不同地点。预期：地点与相关分类正确；创建者评分存在且不占日配额；所需通知记录存在；提交后才触发向量与推送。各入口测试不等于完全相同的故障注入矩阵，缺口见 PLC-01。

### PLC-C02 审核回滚（已有自动化：test:transactions）

前置：一个地点及待审核申请，保存原字段。操作：通过测试已有方式让审核链中写入失败，再执行成功审核。预期：失败时地点、申请状态和相关事务写入不出现半更新；成功时状态与地点一致，审计关联正确。拒绝非法申请也不得修改地点。

### PLC-C03 位置编辑（2bc8c5e，已有自动化：test:place-location）

前置：真实 React/Vite 与测试 API，AMap SDK 替身；创建者、普通访客、管理员和地点。操作：打开管理地点，进入位置选择，移动后取消、确认；保存其他字段后重新读取地点。预期：取消不写位置，确认后经保存写入正确坐标；管理入口权限符合原约定，访客仍走申请流程；卡片和地图更新，不留下选择状态；前后端均无控制台异常。坐标精度和按钮定位以现有断言为准。

### PLC-C04 分享元信息（d285076，已有自动化：test:place-share）

前置：带分类、特殊 HTML 字符和首图的地点，另有无图与不存在地点。操作：GET /p/:id，检查 QQ itemprop、Open Graph、标题、描述、跳转 URL。预期：正确转义；图文规则与 Bot 共享；无图使用站点兜底；不存在地点不生成伪有效卡片。人工环境验证：QQ/微信真实抓取需要部署 nginx /p 转发和平台缓存条件。

### PLC-C05 缩略图安全（已有自动化：test:place-share）

前置：本地合法图片、本站 OSS 图片、外站 URL 与危险路径。操作：GET /p/:id/card-<key>.jpg，并改变图片来源/键。预期：合法图为 300×300 JPG；只允许本站本地/配置 OSS 范围；不任意读取文件、不请求外站；缓存键反映当前首图，失效图有受控结果。

### PLC-C06 创建全链故障注入（待自动化，PLC-01）

分别在创建者评分、分类和通知记录插入点引入错误；对 Web、Bot、日记入口各跑一轮。预期：整个事务回滚，提交后的网络工作不执行；重试成功后只创建一次。不能用当前审核事务测试替代这个矩阵。
