# 地点文字测试案例库

遵循 [执行协议](../../../doc/TESTING.md)。

### PLC-C16 连锁店识别与补标（已有自动化，`test:chain-tags`）

用临时库和 DeepSeek 替身验证店名规范化、品类规则、同名城市统计、描述纯文本、字符串 ID、乱序和不完整回答、单条重试与整批退避、规则升级后的重查、地区等待及初筛后唤醒。核对 `observe` 的地点和评分时钟、`apply` 一次提交已有判断、分类顺序及长度、任何 SQL 分类更新触发的锁定、人工加回和改名解锁，以及地点删除后的清理。比较补标前后的详情、列表、瓦片及标记快照和评分输入，核对无连锁标签的旧分类保留原始画像哈希。检查只读报告的数量、CSV 及 `--classify` 的显式库参数。

### PLC-C14 住民评论展示、初筛和复核（部分自动化：`test:comments`；附近、列表、搜索、瓦片、分享和机器人载荷不带评论待自动化）

地点详情放入 51 条以上可见评论、系统记录、封禁作者和被屏蔽作者的评论，并以游客、作者和管理员读详情。核对最近 50 条的选择和最终 `time`、`id` 升序，以及本人在每种审核状态下都额外返回。核对附近、列表、搜索、瓦片、分享和机器人载荷。使用模型替身分别制造放行、拦下、低置信度、未知原因、超时和无效 JSON，核对请求只有店名、分类和正文。阻塞模型后连改正文，检查旧判定丢弃、重排和重启恢复。覆盖管理员和关闭初筛直接公开、待审重查时撤回旧申请、用完次数后仅更新同一申请、驳回后重新申请。核对待审列表的数据、允许的复核权限、批准与驳回的状态和审计，以及评论改版或删除后的 409 `COMMENT_REVIEW_STALE`。

### PLC-C15 住民评论提交、配额和删除（已有自动化，`test:comments`）

新旧临时库启动后检查旧记录的来源和默认状态。以住民、管理员和未登录访客提交，覆盖无评分、隐藏或受屏蔽地点、非字符串、空白折叠、2 与 200 个码位边界及 emoji。并行提交同一店、修改前更换评分、在北京时间午夜前后达到额度，并以相同正文重试。核对唯一评论、评分及版本快照、首次时间、修改时间和配额。分别从作者删除、管理员删除、地点删除和账号注销入口操作，检查评论及初筛状态消失、待审申请撤回、删除后的模型结果无法恢复评论。用普通住民和管理员分别访问有无 `kind=edit` 的查询，确认权限与系统记录结果。

### PLC-C11 打卡、投喂和公开追加（已有自动化）

`tests/places/test_check_ins.js` 核对投喂写入上次投喂时间（底栏小伙伴的饿 / 饱）、旧库按打卡记录回填，以及 49.99 / 50 米、IP 定位、过期定位、iOS 的小数毫秒定位时间、北京时间跨日、同店重复与第六家限额。用同一认证账号发并行 HTTP 请求，再省略定位重放请求，核对一条打卡与一次投喂。审核覆盖权限拒绝、文本追加顺序、图片去重和预览权限，以及账号或地点删除时清理待审申请。配合私有数值服务运行时，还校验选填评分保存及通过审核后的权重。

### PLC-C01 多入口添加（已有自动化：test:qq-bot / test:ratings / test:journey-publication）

前置：临时库、用户、可用分类、假通知目标。操作：网页路由、Bot 确认、日记公开提交各创建一个不同地点。预期：地点与相关分类正确；创建者评分存在且不占日配额；所需通知记录存在；提交后才触发向量与推送。各入口测试不等于完全相同的故障注入矩阵，缺口见 PLC-01。

### PLC-C02 审核回滚（已有自动化：test:transactions）

前置：一个地点及待审核申请，保存原字段。操作：通过测试已有方式让审核链中写入失败，再执行成功审核。预期：失败时地点、申请状态和相关事务写入不出现半更新；成功时状态与地点一致，审计关联正确。拒绝非法申请也不得修改地点。

### PLC-C03 位置编辑（2bc8c5e，已有自动化：test:place-location）

前置：真实 React/Vite 与测试 API，AMap SDK 替身；创建者、普通访客、管理员和地点。操作：打开管理地点，进入位置选择，移动后取消、确认；保存其他字段后重新读取地点。预期：取消不写位置，确认后经保存写入正确坐标；管理入口权限符合原约定，访客仍走申请流程；卡片和地图更新，不留下选择状态；前后端均无控制台异常。坐标精度和按钮定位以现有断言为准。

### PLC-C04 分享元信息（d285076，已有自动化：test:place-share）

前置：带分类、特殊 HTML 字符和首图的地点，另有无图与不存在地点。操作：GET /p/:id，检查 QQ itemprop、Open Graph、标题、描述、跳转 URL。预期：正确转义；图文规则与 Bot 共享；无图使用站点兜底；不存在地点不生成伪有效卡片。人工环境验证：QQ/微信真实抓取需要部署 nginx /p 转发和平台缓存条件。

### PLC-C05 缩略图安全（已有自动化：test:place-share）

前置：本地合法图片、本站 OSS 图片、外站 URL 与危险路径。操作：GET /p/:id/card-<key>.jpg，并改变图片来源/键。预期：合法图为 300×300 JPG；只允许本站本地/配置 OSS 范围；不任意读取文件、不请求外站；缓存键反映当前首图，失效图有受控结果。

### PLC-C06 创建全链故障注入（待自动化，PLC-01）

分别在创建者评分、分类和通知记录插入点引入错误；对 Web、Bot、日记入口各跑一轮。预期：整个事务回滚，提交后的网络工作不执行；重试成功后只创建一次。不能用当前审核事务测试替代这个矩阵。

### PLC-C11 分层瓦片与防爬（已有自动化：test:place-tiles、test:rate-limit）

前置：临时库，广州三家公开地点（含避雷、待探索、无人均、有 / 无地区）、北京一家、审核中与未通过各一家，一位住民。操作：读清单、字典、三级聚合瓦片和明细瓦片；带旧哈希、不存在的块和不约定的级别请求；enforce 模式下游客按 IP、住民带票据拉明细瓦片，票据被改、过期；新增一家店后作废缓存再读清单；用前端 `markerTiles.js` 与 `placeFilter.js` 读城市级瓦片并筛选；`GET /places`、大 / 小范围 `/places/nearby`、`LEGACY_MARKER_SNAPSHOT=off` 时的 `/places/markers`、超额后的 `/places/:id`。预期：只含公开地点，聚合瓦片里没有 id、店名、精确坐标和描述，三级店数各为 4，匿名行能还原标签 / 人均 / 地区 / 图标类型，只有 z14 一级带 `sub: 16` 与每行的小格编号，前端展开后三家广州店各在自己 1/16 小格（z18 瓦片）的中心；清单与聚合瓦片是 `Access-Control-Allow-Origin: *` 的公共缓存（聚合永不过期），明细瓦片 `private` 且按 Origin 回 CORS、ETag 对得上回 304；旧哈希 302 到当前哈希（保留查询串），不存在 404、`no-store`；游客第二块不同的瓦片 429、同一块再拉不扣额度，票据按账号计、被改过按游客、过期无效；聚合瓦片不限流；新增后只有四块瓦片换哈希、字典不变，内容不变时清单不变；前端读出的匿名点筛选结果与后端数据一致；`GET /places` 回 410，大 / 小范围 nearby 都返回查询范围内所有可见地点及详情，旧快照可关；超额后单店接口 429、登录后按账号。限流本身（IP 段、主体、去重与计次、observe / enforce / off、Redis 与进程内计数、出错放行）见 `test:rate-limit`。

### PLC-C08 地图标记快照与公共缓存（已有自动化：test:place-markers）

前置：临时库，公开、审核中、未通过的地点各若干，一位住民屏蔽了另一位。操作：带不同 `Accept-Encoding` 和 `If-None-Match` 读 `/places/markers`，期间新增地点并作废内存缓存；读公告与出错的公共接口；带 Origin 读 `/places/nearby` 和预检；游客、创建者、屏蔽者、无效 token 读 `/places/overlay`。预期：快照只含公开地点与约定字段、不含描述，br / gzip / 不压缩内容一致，ETag 对得上回 304，内容不变时版本不变；公共接口回 `Access-Control-Allow-Origin: *`、公共缓存头、没有 `Vary: Origin`，出错时 `no-store`；其他接口和预检仍按 Origin 回 CORS；叠加层只给自己的审核中地点和屏蔽的住民的公开地点 id，游客与无效 token 为空。

### PLC-C09 地区补齐与筛选（逆地理部分已有自动化：test:place-regions；地区树与列表筛选待自动化；前端筛选逻辑在 test:place-filter）

前置：临时库，境内（含直辖市、省直辖县级市）、境外、坐标非法的地点，高德逆地理编码替身。操作：跑一轮 `refreshPendingBatch`，再挪动一个地点的坐标后重跑；让替身返回 QPS 超限、整批 `INVALID_PARAMS`、网络错误；读 `/places/regions`，用 `/places/list?province=&city=&district=` 筛选。预期：直辖市的市为省名、县级市的市为区县名；境外记为已查、省市区为空，不在高德境内格子里的不发请求；海外配额用完整批被拒时逐个重查，只把被拒的点记为空，全部被拒时不写表；挪动后只重查该地点；限流重试后成功，整批被拒时逐个重查且只把被拒的点记为空；网络错误不写表；不更新 `Place` 行（评分时钟不变）；地区树只含公开地点、按数量降序、`bounds` 覆盖其地点；只给 `city` 不给 `province` 时不筛选。

### PLC-C10 标签合并与待探索（待自动化）

前置：`categoryMerges.json` 里一组源 → 保留标签，临时库含带源标签的地点与待处理申请。操作：网页 / Bot / 日记各新建一个带源标签的地点，`POST /categories` 新建源标签；对库运行 `categories:merge` 预览后 `--apply`；新建一个带“待探索”的地点。预期：新写入一律是保留的标签且去重、顺序不变；预览不改库，应用前有备份，只改 `Place.category` 与 pending 申请，不改 `updated_time` / `updated_by`；“待探索”地点没有创建者评分、不占配额，`rating_input_kind` 为 `none`。

### PLC-C12 修改申请的取代与最近修改（已有自动化：test:place-requests）

前置：临时库、创建者、两位访客、管理员和一个地点（最近修改为创建者）。操作：同一访客经两个入口连续提交三条修改申请，另一访客提交一条，再插入同一访客的打卡申请；批准最新一条和另一访客的申请；插入夹带 `creator_id` / `updated_by` 的旧申请和申请人已删除的申请后批准。预期：同一访客只剩最新一条 pending，之前的为 `superseded` 且不能再审，审计记下被取代的申请 id；别人的申请和打卡申请不受影响；只含所有者 / 修改人字段的提交 400 `EMPTY_PLACE_REQUEST`，夹带的字段入库前剔除、批准时忽略；批准后所有者不变，`updated_by` 为申请人、`updated_time` 更新，申请人已删除时保留原 `updated_by`。

### PLC-C13 描述最少 15 字（已有自动化：test_place_coordinates，Bot 部分 test:qq-bot）

前置：临时库、创建者、访客和一个地点。操作：新增时不写描述、写两个字、15 个字中间夹空格凑长度、正好 15 个字、14 个字加一个 emoji；编辑把描述改成两个字；把库里描述改成很短的老描述后，只改人均且描述原样（带首尾空白）提交；访客提交描述太短的修改申请、描述原样只改人均的修改申请。预期：不写、太短、靠空格凑的都 400（提示至少 15 个字），正好 15 个字和 emoji 算一个字的通过；改短的编辑 400 且不改库；描述没改的编辑和申请照常通过；太短的申请 400 `PLACE_DESCRIPTION_TOO_SHORT`。

### PLC-C07 坐标范围（已有自动化：test_place_coordinates / test:place-location）

前置：临时库、创建者、访客、管理员和一个地点。操作：新增、编辑、提交修改申请时使用纬度超出 ±85.0511°、经度超出 ±180° 或非数字的坐标；审核一条修复前已入库的越界申请；对库中直接写入的越界地点运行 `places:check-coordinates`；添加模式下点击地图边界外。预期：写入全部 400 且不改库，越界申请不能批准但可驳回；检查脚本列出越界地点与申请、退出码 2，干净库退出码 0；界外点击只提示，不打开添加表单。
