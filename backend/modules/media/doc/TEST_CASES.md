# 图片文字测试案例库

遵循 [执行协议](../../../doc/TESTING.md)。已有自动化入口 `npm run test:images`；分享额外用 `test:place-share`。临时 UPLOADS_DIR、临时库、本机 OSS 替身；绝不访问真实 bucket。

- MED-C01 内容嗅探：上传合法 JPEG 但文件名 photo.html，再上传伪装 .jpg 的非图片；预期前者按真实格式入库，后者被拒。体积超过上传上限也不得写文件。已有自动化。
- MED-C02 元数据与方向（d285076）：准备带 Exif/XMP/IPTC 的 JPEG、带方向标签图片和带元数据 PNG/WebP；上传后重新解析。预期敏感元数据消失、显示方向正确；可直接移除段的 JPEG 不重复有损编码，断言像素/编码适用不变量而非只比较大小。已有自动化。
- MED-C03 local 与 OSS：相同合成图片分别上传两模式；预期本地公开 /uploads 路径或配置自有域名/本站前缀；扩展名与 Content-Type 一致，不泄露厂商默认域名。已有自动化。
- MED-C04 历史链接与穿越：本地缺失、安全嵌套路径、危险编码路径；请求 /uploads。预期 OSS 模式安全路径 302，危险路径无有效外部重定向，不跨目录读文件。已有自动化。
- MED-C05 历史数据修复（2eadd01）：数据库包含多层 JSON、坏值、失效本地图；先预演再显式 apply。预期预演不写；apply 备份后只改目标字段；缺失比例保护不能用“本机无上传目录”绕过。已有自动化中的 repair helper / 迁移组，生产恢复演练另见 MED-01。
- MED-C06 OSS 迁移幂等：本机假 OSS，临时 Place / PlaceRequest 图片引用；预演、apply、重复 apply。预期仅缺失对象上传，备份存在，引用按规则改写，重复执行不重复破坏数据；头像和私有日记 BLOB 不迁。已有自动化。
- MED-C07 断网和恢复演练（待专项验证，MED-01）：在上传和引用改写边界引入失败，对照备份恢复并校验引用/对象。预期恢复过程有可执行步骤与结果，不能把“生成了备份”当作“恢复已验证”。
