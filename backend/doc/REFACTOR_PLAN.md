# 后端模块化整理计划

基线：`2bc8c5e`，日期：2026-10-15。目标是让维护者和 AI 按业务找到代码、证据与回归入口。

## 范围与约束

- 按业务组织 `modules/<业务>/routes|services`，共用技术能力组织到 `infrastructure/`，HTTP 中间件组织到 `http/middleware/`。
- 自动化测试组织到 `tests/<业务>/`，运维命令组织到 `scripts/<用途>/`。保留现有 npm 命令名和 HTTP URL。
- 不改算法、数据库表、业务权限、环境变量和运行数据位置；SQLite、uploads、logs、seeds、.env 仍相对于 backend 根目录。
- 文档保存在 backend 下，避免根 `/docs` 忽略规则导致交付物未被 Git 收录。
- 不增加依赖、不运行真实模型探测、不给机器人发送消息、不迁移实际数据。

## 执行步骤

1. 记录关键测试基线，核对 Git 提交及实际代码，生成旧路径到新路径的完整对照表。
2. 搬迁业务、基础设施、测试和运维代码，统一重写相对导入及文件路径。用单一 `infrastructure/paths.js` 固定 backend 根目录。
3. 为每个业务模块补 `doc/README.md`；复杂流程补独立案例库。集中维护架构对照、Git 历史与待办，避免重复记录。现有专题文档原文保留并迁移。
4. 增加不加载业务的目录/导入检查和安全的测试汇总命令。运行全部本地后端测试及浏览器集成测试，检查路径对照、文档链接、差异与运行数据位置。

## 验收与重点风险

- `npm test`：所有离线后端测试通过；`npm run test:ui`：真实前后端集成回归通过。
- `npm run test:structure`：相对导入可解析，根目录路径稳定，各模块都有可访问文档。
- 原 npm 命令名不变；前端调用 API 不变；测试替身的 `require.cache` 必须指向迁移后的同一个文件。
- 特别检查数据库 seed、日志、上传位置、子进程内嵌 require、测试访问前端源码和图片迁移脚本的位置。
- Git 历史中的已修复内容单列；待办需有代码或历史依据、影响、建议验证，不能把猜测写成已确认缺陷。
