# 匿名地点转明细后的坐标精修回归

2026-11-24，基线 `a87cd00`。用户确认问题覆盖所有网页端，发生于匿名瓦片地点切换为带名称明细后的缩放过程。本轮修改仅位于网页 Worker 计算运行时，恢复既有锚点精修行为。

## 原因与修正

一对一跨档标记先沿用匿名格子的地理锚点，避免明细到达瞬间跳动；继续放大后，应在既有 0.25 级进度内修正到更精细坐标。此前 Worker 只在短暂的 `refine` 请求中推进坐标。桌面路径的最终 `camera` 请求可能使中间请求过期，触屏路径还会推迟整个手势内的标记更新，最终请求均没有推进精修，因而一直保留匿名格子的坐标。误差随放大增加。

Worker 现在保存已提交快照的实际相机缩放值，最终相机结果也按已提交进度推进坐标精修。这与“中间精修请求保持聚合层级”的逻辑独立；最终相机仍能正常合并/拆分。未确认的候选结果不会成为进度基准。初次跨档原位显示、静止/平移以及缩小时保持当前锚点的规则继续生效。

## 自动化证据

修改前，真实控制器和 Worker 的跨档回归在桌面、触屏、缺少 SDK 事件三条路径全部失败：最终相机提交后坐标仍未修正。修复后，夹具的初始经度误差 0.002° 在继续放大 0.1 级后减少到约 0.0012°，放大到 0.4 级后释放临时锚点并采用精确坐标。缩小和静止不推进、不倒退，正常逻辑缩放级别能够更新。

真实高德 SDK 另用一个匿名格转一个命名地点，检查标记 DOM 的零尺寸地理原点。z13 跨档保留初始锚点；继续放大至 z14、z16 后，标记坐标为精确地点，屏幕原点与 `lngLatToContainer` 的精确投影误差均为 0.015625 CSS 像素，断言阈值 2 CSS 像素。环境：Windows、Edge 158.0.4370.33、headless、GPU 关闭、1100×700 地图，地点为合成夹具。该结果是夹具坐标检查，不是所有设备帧率或 iOS 真机验收结论。

实际通过：`npm test`、`npm run build`、`npm run test:map-anchor-browser`、现有 `test:map-touch-browser`、`test:map-review-browser`、`test:map-motion-browser`、`test:native-clusters-browser`。Vite 仍输出既有大 chunk 提示。

Worker 协议断言已接入 `npm test`，避免仅检查成员计数和动画对象而漏掉坐标。原始日志在本地忽略目录 `docs/map-performance-work` 的 `anchor-refinement-red.log`、`anchor-refinement-green.log`、`anchor-real-amap.log`、`anchor-full-tests.log`、`anchor-build.log` 等文件。

人工复验应使用当前修复版，按匿名档→显示名称→继续放大→缩小→平移的顺序核对真实地点锚点。本轮没有部署线上版本。
