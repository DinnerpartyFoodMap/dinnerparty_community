# AI 测试案例执行协议

案例是可复用的测试说明，不能因为写在文档中就标成已通过。每个案例需给出前置状态、动作、可见结果、状态/网络副作用和现有自动化入口；覆盖不足明确记为待自动化。当前结果在 [验证记录](VERIFICATION.md)。

## 执行约定

- 从 frontend 运行 npm 命令，或仓库根用 npm --prefix frontend。先看模块 doc 与 [待办](HISTORY_AND_TODO.md)，再看实际断言。
- 逻辑测试不加载正式 App 和真实 SDK；测试模型/地图/QQ/OSS 边界只用可控替身。Node JSON loader 在 scripts/support，因后端测试引用而保留路径。
- 浏览器集成由 backend/tests 启动真实 React/Vite/Express、临时库与测试用户；只替换外部模型、地图等边界。`npm run test:ui` 转发后端命令，需要前后端依赖和可用 Playwright/browser channel。
- 触发动作后等待可观察状态或网络结果，不用固定 sleep 冒充完成。断言按钮状态、可见内容、服务器结果、数据库最终副作用和页面异常。
- 每个异步场景至少考虑：关闭面板、切换目标、切换账号、失败后重试、旧响应晚到。增加取消不能误删仍需提交的用户数据。
- 本地存储使用合成账号与隔离浏览器上下文；不要读改真实用户凭证或草稿。后端 DB_FILE/UPLOADS_DIR 用临时位置。
- 桥接逻辑测试检查字段过滤、请求关联与过期会话；真机验证另外记录系统、应用与协议版本，不能把 bridge 替身通过当作 Swift/Android 已构建。
- UI 文案经 i18n，交互断言可以用固定测试语言的可访问名称；改目录须同步 AST 文案检查的数据白名单，不删检查来放行。
- 报告命令、退出状态、覆盖范围、缺口和首次失败/复跑情况。不得用历史截图或旧文档数字冒充本次证据。

## 命令矩阵

| 命令 | 实际覆盖 |
| --- | --- |
| npm test | 原有平台、地图、overlay、评分、原生地图/设置、日记文本、i18n，加结构检查 |
| npm run test:structure | 解析全部受检 JS/JSX/MJS；相对导入含图片/CSS，模块文档与链接，前后端 harness 入口 |
| npm run test:platform | 配置、坐标、返回、凭证辅助与平台纯逻辑；不是所有原生能力的端到端覆盖 |
| npm run test:map | 聚合、快照、转场、范围缓存、请求闸门、底图等纯逻辑 |
| npm run test:overlay | backdropPress 点击/触摸守卫；不代表每个弹层均有浏览器覆盖 |
| npm run test:rating | 评分展示规则与请求封装；组件生命周期另需交互测试 |
| npm run test:native-chrome | JS 地图与设置桥接会话、清洗和请求响应；实际顺序包含两个测试文件 |
| npm run test:journey-text | 原文片段分配与重叠逻辑；完整日记在浏览器/后端测试 |
| npm run test:i18n | 默认语言键、插值、源码硬编码与登记的数据值 |
| npm run build / build:mobile | Web/移动产物构建；移动配置检查不等于原生签名或真机验收 |
| npm run test:ui | 两套真实集成：地点位置和日记；不是全站页面浏览器覆盖 |

## 案例级别

`已有逻辑自动化`、`已有浏览器自动化`、`待自动化`、`人工真机验证`。部分案例同时有两级覆盖时写清各自范围。高风险用户流程的优先级：认证与账号切换、地点写入与编辑、草稿保存/公开、返回与弹层、原生桥接降级。
