# 网页地图缩放时标记闪烁

2026-11-24，基线 `d7dc336`（标记控制器与 `03bc17e` 相同）。用户反馈网页地图缩放时标记点一闪一闪。

## 原因

标记的增删改按帧分片调和，真实高德 SDK 每添加一个标记约 1ms，几十个标记要 100–200ms，上百个要 1s 左右。连续缩放时，上一步的调和还没做完，下一步缩放就开始了：

1. `movestart` 时 `_onMoveStart` 取消进行中的调和，并按上一份已提交快照重新调和（`_cancelRender` 的恢复分支），刚显示的新标记被撤下，旧标记重建；
2. 这一步缩放结束后提交新快照，新标记再次出现。

滚轮每一格都重复一次，同一批标记反复消失、出现。`_commit` 与 `update` 进入时也走同样的取消与恢复。

## 修改

- 相机开始移动、提交新相机或新数据时，不再取消进行中的调和，也不退回上一份快照。相机移动后，这次调和不再起动画或残影，剩余节点直接就位；新结果到达时由 `_apply` 从当前已显示的标记接着调和。
- `_receive` 不再等调和完成才返回，计算调度可以立即处理相机停下后的新请求，新结果直接接替进行中的调和。原先取消调和时会顺带放开调度，去掉取消后若仍等待，慢设备上最新的相机结果要排在过时的调和后面，晚几秒才显示。
- 页面切到后台时仍按原样取消并恢复，回到前台再重新同步。
- `test:map-review-browser` 原先断言“相机移动时退回上一份快照”，改为断言已显示的标记不撤回、调和完成到目标快照、相机移动后不再起转场。

## 回归测试

`npm run test:map-flicker-browser`：真实高德 SDK 与 Worker，4000 个合成地点，地图 1000×700，起始 14 级。滚轮模式依次做快速放大、快速缩小（每格间隔 40ms，各 24 格）、慢速放大、慢速缩小（每格 250ms，各 12 格），范围 14–17.5 级；触屏模式做 6 次连续双指放大、6 次连续缩小，每次间隔 180ms。每帧记录屏幕内可见的标记（残影算可见，透明度低于 0.3 不算），标记在 20 帧内消失后又出现计为一次闪烁，可见数量在 10 帧内跌到一半以下又恢复计为一次骤降。

环境：Windows，Edge 158.0.4370.33 headless，GPU 关闭，Node.js 24.19.0。

| 控制器 | 输入 | CPU | 闪烁 | 骤降 | 退回旧快照 |
| --- | --- | --- | --- | --- | --- |
| 修改前 | 滚轮 | 1× | 201 | 0 | 33 |
| 修改前 | 滚轮 | 4× | 12 | 0 | 19 |
| 修改前 | 双指 | 1× | 0 | 0 | 29 |
| 修改前 | 双指 | 4× | 0 | 0 | 29 |
| 修改后 | 滚轮 | 1× | 0 | 0 | 0 |
| 修改后 | 滚轮 | 4× | 0 | 0 | 0 |
| 修改后 | 双指 | 1× | 0 | 0 | 0 |
| 修改后 | 双指 | 4× | 0 | 0 | 0 |

双指夹具中修改前也会退回旧快照，但触摸期间调和暂停，退回的调和在新结果到达前几乎没有执行，没有出现可见的闪烁；真机上手势间隔与 CPU 不同，是否出现未验证。最长一次调和耗时修改前后相近（1× 约 0.9s 与 1.1s，4× 约 11.8s 与 13.3s，含测试每帧取样的开销）。

同时通过：`npm test`、`test:map-review-browser`、`test:map-touch-browser`、`test:map-anchor-browser`、`test:map-motion-browser`、`test:map-compute-browser`、`test:map-render-browser`、`test:native-clusters-browser`。iOS 原生底图的标记由 `nativeMarkerLayer.js` 处理，不经过这里的分帧调和。
