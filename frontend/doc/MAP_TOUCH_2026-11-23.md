# 网页地图触摸缩放验证

2026-11-23，基线 `4be4a8c`。用户在 iPhone/iPad Chrome 上反馈缩放后长时间不更新、缺少拆合动画。本轮未连接物理 iOS 设备；以下复现及通过结论仅针对列出的自动化环境。

## 复现与原因

Windows / Node 26.12.1 / Edge 158.0.4370.33，真实高德 2.0 SDK、1000×700 地图、5000 个合成地点、可信 CDP 双指输入。浏览器仍是 Chromium；设置 iPhone Chrome UA 仅用于触发移动网页路径，不是 WebKit。

以地图中心为轴执行固定双指放大时，夹具可重复捕捉到 SDK 中心成为 `LngLat(NaN, NaN)`，`getBounds` 无法读取；缩放值却从 13 变到约 15.22，SDK 未发出正常相机结束事件。标记仍停在 13，页面也无法按新视口换瓦片档。偏离中心、带平移的对照手势可以产生正常事件。单独调整标记 bubble 或取消 pointerdown 不能修复该夹具，未纳入产品修改。

另一个可复现的边界是 SDK 在手指仍按住时发出中间 end：此前会立即提交标记、移除触摸起点。异步渲染和清理必须服从完整的物理触摸会话。

## 本次修改

- 首次触摸记录有效相机中心。最后一指抬起后，在 SDK 收尾的下一帧检查相机；只有非有限相机才恢复最近有效中心，同时保留此次缩放值。
- 有效恢复锚点在新的触摸打断恢复帧、页面隐藏时保留；前台返回重新尝试恢复，有效相机则直接沿用。新的有效手势会刷新锚点。
- 触摸期间暂停标记创建和回收，中间 SDK end 不提交。最后一指抬起后观察实际视口稳定 50ms，再恢复渲染并提交；容器外抬手、取消、销毁和页面隐藏均清理会话。
- 稳定视口回调同时通知 MapView 读取最终瓦片档，覆盖 SDK 缺失结束事件的路径；前台恢复也等待可读视口，避免只修复底图而标记仍不更新。

## 验证结果

新增测试在修复前明确失败：可信双指后标记层级落后；中间 SDK end 提前替换触摸目标；缺失 end 无法通知瓦片档；NaN 相机无法恢复。独立审查又复现了“下一次触摸/后台切换取消恢复帧并丢掉有效中心”的永久冻结路径，补充失败用例后修正并复审。

实际执行并退出 0：

- `npm test`、`npm run build`。保留已有的 Vite 大 chunk 提示。
- `npm run test:map-touch-browser`：生命周期边界及真实 SDK 连续放大/缩小/放大，最终可见标记 87，标记逻辑级别 15、地图 15.44，遵循既有滞回。测试通过计算样式与实际位移确认分裂/汇合均可见。
- `FOODMAP_CPU_RATE=4` 下的同一触摸回归。
- 既有 `test:map-compute-browser`、`test:map-render-browser`、`test:map-review-browser`、`test:map-motion-browser`、`test:native-clusters-browser`。

新增恢复和前台返回检查不把固定等待当作成功，按可观察的恢复、视口、回调和队列状态完成。按住期间的短等待仅用于断言这段时间没有提前提交。

原始日志位于本地忽略目录 `docs/map-performance-work`：`touch-gesture-red.log`、`touch-lifecycle-red.log`、`touch-recovery-review-red.log`、对应 green 日志、`touch-gesture-cpu4.log`、`touch-full-tests.log` 与 `touch-build.log`。合成地点不写入真实后端；真实联网仅用于公开 SDK 配置和高德底图。

## iOS 人工验收缺口

物理 iPhone/iPad Chrome 尚未验收，不能据 Chromium 结果宣称这些设备已通过。需要在确认加载当前修复版后检查：中心/偏心双指大幅放大缩小、动画中再次捏合、一指先抬起再松手、缩放中切后台返回、冷缓存跨瓦片级别，以及原来的单点和聚合点按。应记录访问地址、iOS/Chrome 版本和具体失败步骤。
