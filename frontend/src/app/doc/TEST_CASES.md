# 应用协调文字案例

遵循 [AI 执行协议](../../../doc/TESTING.md)。App 本身没有独立完整浏览器测试；下列只有明确标注的辅助能力有现成自动化。

### APP-C01 冷启动恢复（待浏览器自动化，APP-02）

前置：原生安全存储有合法 token，恢复 promise 暂不返回。操作：启动并尝试需登录入口，再释放恢复和 /users/me 响应。预期：恢复前不闪现“已退出”或清空凭证；完成后显示相应用户；恢复失败与游客有可解释状态。辅助 token 解码有 test:platform，不代表此流程已覆盖。

### APP-C02 网络故障与明确拒绝（待自动化）

前置：有效本地 token。操作：分别让账号核对断网、超时、401/403/404。预期：按现有规则，网络失败保留凭证可重试；明确拒绝才清除。记录存储、请求、用户和页面状态四者，不只看菜单。

### APP-C03 快速换账号与旧响应（待自动化，APP-02）

前置：A 的核对请求未返回。操作：退出并登录 B，再返回 A 的响应。预期：A 不能覆盖 B 用户、主题、地图画像或会话；旧 token 不因迟到响应重新持久化。要验证受影响消费者的状态，而非只验证 App 中一个变量。

### APP-C04 导航与地图常驻（部分集成覆盖）

前置：地图已定位、加载视口和打开业务页。操作：地图 → 设置/聚餐 → 返回，含浏览器后退和原生返回。预期：地图不因路由切换反复初始化，视角与缓存按原行为保留；覆盖期间不会误触底层；URL 与可见页一致。test:platform 检查返回辅助，日记/位置 harness 不加载完整 App，完整流程仍待自动化。

### APP-C05 离开保护与原生设置回退（待自动化）

前置：有未同步草稿，另建一个原生设置不支持/失败场景。操作：导航离开、取消离开、再保存后离开；打开设置失败。预期：离开保护不丢草稿；取消不改变路由；桥接不可用回网页设置且无重复页面。日记离开保护有现有日记浏览器覆盖，但 App 路由集成另验。
