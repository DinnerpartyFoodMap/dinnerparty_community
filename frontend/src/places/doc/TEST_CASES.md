# 地点交互文字案例

遵循 [执行协议](../../../doc/TESTING.md)。

- PLC-FC01（已有逻辑，test:rating）：给出有分/无分、避雷标签、2.5 边界与四档；调用 rating 展示函数。预期有人评分以综合分为准，无分才看标签，舍入和提示符合既有规则；与后端 test:ratings/test:search 同跑以防漂移。
- PLC-FC02（已有请求逻辑，test:rating）：替身 fetch 捕获读取/提交/撤回的 URL、token、body、signal 和错误响应；预期端点、整数分与错误处理不变。不能从此推断组件换地点时不会被迟到回调覆盖。
- PLC-FC03（已有浏览器，test:ui 位置流程）：编辑文字后选点取消/确认，直接保存或申请审核；预期其他表单内容保留，取消不持久化，服务器成功后地图/详情一致。
- PLC-FC04（待浏览器，PLC-F01）：A 地点评分保存未完成时切 B 或切账号，再返回 A 结果。预期 A 的摘要只影响 A，不能在 B 面板显示 A 的配额/自己的分；saving 状态不能被旧操作错误复位导致重复提交。
- PLC-FC05（待浏览器）：图片队列选择、取消、上传失败再重试，期间关闭/重开表单。预期已有图片与文字不丢，不把未上传本机地址提交服务器；图片压缩逻辑本身由 platform 案例核对。
- PLC-FC06（已有部分集成 + 人工）：从地点展开相关日记、切地点导致旧日记请求晚到，点击分享/复制/导航再取消。预期相关内容不串地点；仅按真实操作完成口径记录行为。日记列表迟到覆盖已在日记 harness，系统分享实际收件不属于自动化保证。
