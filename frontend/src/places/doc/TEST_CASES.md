# 地点交互文字案例

遵循 [执行协议](../../../doc/TESTING.md)。

- PLC-FC11（重试顺序有单元测试，Web / Android / iOS 入口待真机覆盖）：打开已收录的公开地点，从店卡点击打卡，分别验证无定位权限、低精度、界外和小于 50 米的场景。仅提交定位即可成功和投喂。提供可选评分、描述及照片后，检查评分回执、待审核提示和审核后的地点照片。网络丢失响应时，重试先查询同一请求，再按需重新定位。切换地点、账号或离开页面时，旧打卡面板随之关闭。

- PLC-FC01（已有逻辑，test:rating）：给出有分/无分、避雷标签、2.5 边界与四档；调用 rating 展示函数。预期有人评分以综合分为准，无分才看标签，舍入和提示符合既有规则；与后端 test:ratings/test:search 同跑以防漂移。
- PLC-FC02（已有请求逻辑，test:rating）：替身 fetch 捕获读取/提交/撤回的 URL、token、body、signal 和错误响应；预期端点、整数分与错误处理不变。不能从此推断组件换地点时不会被迟到回调覆盖。
- PLC-FC03（已有浏览器，test:ui 位置流程）：编辑文字后选点取消/确认，直接保存或申请审核；预期其他表单内容保留，取消不持久化，服务器成功后地图/详情一致。
- PLC-FC04（待浏览器，PLC-F01）：A 地点评分保存未完成时切 B 或切账号，再返回 A 结果。预期 A 的摘要只影响 A，不能在 B 面板显示 A 的配额/自己的分；saving 状态不能被旧操作错误复位导致重复提交。
- PLC-FC05（待浏览器）：图片队列选择、取消、上传失败再重试，期间关闭/重开表单。预期已有图片与文字不丢，不把未上传本机地址提交服务器；图片压缩逻辑本身由 platform 案例核对。
- PLC-FC06（已有部分集成 + 人工）：从地点展开相关日记、切地点导致旧日记请求晚到，点击分享/复制/导航再取消。预期相关内容不串地点；仅按真实操作完成口径记录行为。日记列表迟到覆盖已在日记 harness，系统分享实际收件不属于自动化保证。
- PLC-FC07（已有逻辑，test:share-card）：卡片数据与版式（空字段回退、店名/地址截断、坐标越界、缩放回落、地图请求尺寸、二维码与信息区不重叠）；绘制本身需浏览器。预期换店再生成不沿用上一家的图片，横竖切换复用缓存，关闭面板释放图片地址。
- PLC-FC09（已有逻辑，test:place-filter / test:rating / test:native-chrome；地图移动待浏览器）：设省、省 + 市、省 + 市 + 区筛选，只给市不给省，再清除；地图点击时取 `placeFilterSnapshot`。预期：规整结果与后端 `parseRegionFilter` / `mapClickFilter` 一致，缺上层时不生效，无生效条件的快照为 null；地图移到所选地区范围；iOS 原生面板的 `menu` 分组回传行 id 后筛选一致。
- PLC-FC10（待自动化）：添加地点表单勾选 / 取消“待探索”，以及在标签选择器里直接加 / 去该标签；再给带“待探索”且 0 / 1 条评价的地点。预期：勾选框与标签串同步，勾选后清掉已选评价、提交不要求评价；0 条评价时 `isUnexploredPlace` 为真、标记为问号图标（`placeGlyphKind` 为 `unexplored`），有评价后为普通图标；高德未收录地点为 `add` 图标，展会地点仍为普通图标。
- PLC-FC08（已有逻辑，test:place-draft；浏览器人工）：添加地点填写文字/评价/图片后点遮罩、下滑、返回键或取消关闭，再在地图上点选或从同一高德地点收录。预期内容恢复并提示可清空；从另一个高德地点收录时先显示该地点信息、草稿可选恢复；改回空表单、提交成功或账号注销后草稿删除；草稿按账号隔离。
- PLC-FC13（快照与桥接已有自动化：test:rating 的 test-native-place-sheets、test:native-chrome；iOS 真机待验证，Swift 未编译）：iOS 原生控件接管时，从店卡点「评价」与「打卡」。评价：未登录、没人评价、加载中 / 失败、有分布与预测、低分风险、自己评过、今日次数用完、受限账号；依次点格子、撤回、在保存失败时看提示。打卡：输入补充描述（含输入法组字、超过 1000 字）、选 / 取消评分、选 3 张照片后删一张、提交中点关闭 / 下滑 / 点地图、成功后完成、评分未保存时重试。预期：两个面板都是与筛选、收藏同一种玻璃面板，关闭后回到原店卡；评价快照的档位颜色、分布条、选中格与网页一致，失败原因写在面板里；打卡输入不被回声打断，提交中面板不关闭、地图不响应，结果与网页面板相同；网页面板只在网页工具栏时出现。

- PLC-FC14（纯逻辑已有自动化：test:rating 的 test-place-comments，原生表单白名单 test:native-chrome；界面流程待浏览器，iOS 真机待验证，Swift 未编译）：住民评论。游客、普通住民、封禁账号分别打开公开地点、自己审核中的地点、高德临时地点；从描述末尾、网页店卡操作栏的“评论”、iOS 原生店卡详情点“写评论”（iOS 原生评论表单提交曾因缺店名被网页拒收，显示“提交失败，请稍后重试”）；写 1 个字、201 字、带换行的评论，不选 / 改选评价后提交；再修改、删除。预期：游客点入口先登录；不满足条件时没有入口；字数不对或没选评价时表单里提示、不发请求；评价有变化才调用评价接口；提交后描述末尾立刻出现自己的那条并标“审核中”，初筛结束后小字消失或变成“未通过审核”；别人只看到公开的评论；删除后整行消失。iOS 原生卡片的简介末尾同样逐行显示，超长时最后一行提示还有几条。
- PLC-FC12（浏览器与桥接，iOS 真机待验证）：给地点返回 `3.6` 的有效预测，打开地点列表、网页地点卡和评价面板，检查“预计你会给”仅强调 `3.6`。`test:native-chrome` 检查原生卡片接收同一个单独的数字，并过滤无法在副标题中匹配的值。实际字号、长字幕换行及 VoiceOver 用 iOS 真机检查。
