# 认证界面文字案例

遵循 [执行协议](../../../doc/TESTING.md)。完整表单场景均待浏览器自动化（AUTH-02）；后端 test:qq-verification 验证服务端规则，不代表下面交互已覆盖。

### AUTH-C01 登录成功与失败

前置：隔离浏览器，假接口返回合法 token/user、错误密码、非 JSON 错误或缺字段成功体。操作：填表提交、连续点击。预期：忙时防重复；成功仅调用一次登录回调；无效 payload 不进入已登录态；错误提示可见且不显示密码/token，必要时带安全 requestId。

### AUTH-C02 发送验证码与冷却（d285076）

前置：注册与重置模式，合法/非法 QQ，伪发送接口。操作：空 QQ、格式错误、发送成功、60 秒内再次发送、小时级限流。预期：非法输入不发请求；用途正确；倒计时与重试提示符合响应，长等待只提示；切模式时不把另一用途的验证码当有效提交。

### AUTH-C03 关闭取消与迟到响应

前置：提交请求和发送码各保持未完成。操作：关闭面板或切模式，再让旧请求成功。预期：请求被取消或其结果忽略；关闭后不能登录、弹出错误或把旧倒计时写进新面板；重新打开后可正常提交。对 fetch 与 iOS Chrome XHR 两路径都执行。

### AUTH-C04 超时、重试与请求关联

前置：可控时钟、无响应上游，准备响应头 requestId 与非法 ID。操作：超过普通/发送码各自超时，再重试成功。预期：只结束对应当前请求；重试不被旧 timer 取消；界面回到可操作状态；安全 ID 可追踪，非法 ID 不直接展示。

### AUTH-C05 注册与密码重置

前置：白名单 QQ、已占用 QQ、绑定冲突和合法重置账户，接口返回已覆盖的服务端结果。操作：短密码、错码、合法注册/重置。预期：字段错误保留可修正内容；成功按既有回调更新身份；重置后旧会话状态需由后端回归核对，前端不伪造成功。

### AUTH-C06 真实浏览器兼容（人工真机验证）

在 iOS Chrome、Safari、Android WebView 分别验证键盘、自动填充、提交/取消、XHR/fetch、前后台恢复。记录实际系统和浏览器版本；不能以 Node fetch 通过宣称兼容路径通过。
