# 原生工程与人工验证

frontend/ios 是 Xcode/Swift 工程，含原生地图 chrome、设置、键盘与 WebView 协调；frontend/android 是 Android/Capacitor 工程；native/ios 保存相关原生来源文件。它们本轮不搬迁，JS 入口与协议见 [platform](../../src/platform/doc/README.md)。

流程：Web/mobile 构建 → Capacitor sync 与仓库补丁 → 对应平台原生构建/签名 → 测试设备安装 → 权限/生命周期/键盘/桥接验证。此流程记录供维护，不表示本次执行了 sync、签名或发布。

采用 platform 适配加部分原生 UI，对照全平台各写一套业务，能复用数据规则；代价是必须同时维护桥接协议、项目文件和真机覆盖。新 Swift 文件需要 Xcode 项目引用，不能只新增源码；原生工程内路径属于构建系统，不随 JS 业务目录调整。

已有 [iOS 玻璃验收清单](ios-glass-checklist.md) 保留。另需真实设备验证账号恢复、相册/定位权限、系统返回、分享取消、App 前后台、原生设置关闭及协议降级；Node bridge 检查不能替代这些环节。本次范围与限制见 [验证记录](../../doc/VERIFICATION.md)。

Android 定位使用高德定位 SDK（应用内插件 AMapLocationPlugin）；模拟器复现、修复与真机覆盖边界见 [定位回归记录](android-location-checklist.md)。

## 多活动展示（2026-10-26）

iOS 首页与后台复用网页活动组件：后台逐项新增、编辑、下架和填写举办地时间；首页堆叠显示数量，随机初始化起点后按活动时间每 10 秒轮换，点击展开全部活动。展开列表登记到统一浮层栈，暂时收起原生地图控件并接管返回操作。选择活动后由原生卡片展示详情，轮播不会改变所选活动。

原生卡片从已有 `paragraphs` 中读取 `event-time`，在摘要显示日历图标和时间，详情不重复显示。协议保持 v11，旧原生版本仍能在详情段落看到活动时间。切换活动或重新打开卡片时分配新 token，刷新同一活动时保留 token 和展开状态，防止旧原生回调作用到新活动。

验证：前端全量测试、移动构建、`capacitor sync ios` 和 iOS 工程补丁通过；同步后的网页文件与构建产物逐文件校验。Windows 环境未执行 Xcode 编译、签名或真机测试。待 iOS 设备检查：多个活动的随机轮播和展开选择、原生卡片时间与 VoiceOver、打开详情期间轮播、切换活动后的关闭/场馆/附近随机操作、展开列表时返回手势，以及 App 前后台恢复。

## 地图明暗主题回归（2026-10-21，待 iOS 26+ 真机执行）

工具栏与地点卡共用 MapChromeHostingController，按桥接快照的 theme.dark 同步 UIKit 外观；SwiftUI 内容使用同一地图主题。WebView 保留系统外观，以便“跟随系统”仍能读取真实的系统偏好。

| 前置状态 | 操作 | 预期可见结果 |
| --- | --- | --- |
| 系统深色、地图强制浅色；系统浅色、地图强制深色 | 冷启动，打开搜索、更多功能与收藏 | 工具栏、玻璃底、文字和输入框始终跟随地图主题 |
| 系统主题与地图相反 | 第一次打开地点卡，收起后换地点重开，上滑至全屏 | 从弹出动画第一帧起，卡片内容、玻璃底与全屏底色均跟随地图，无约 0.2 秒明暗切换 |
| 地点卡已打开或正在弹出 | 切换地图浅色/深色主题 | 工具栏与卡片内容、玻璃底同步更新，无需关卡重开 |
| 地图分别设为固定浅色、固定深色、跟随系统 | 在系统设置切换明暗，返回 App | 固定主题不变；跟随系统模式正确响应系统切换，无 WebView 外观反馈循环 |
| 地点卡上方打开系统分享或大图预览 | 取消后重开地点卡 | 呈现不冲突，恢复后的卡片从首帧使用当前地图主题 |

这些场景需要重新构建并安装 iOS App；前端 npm 测试不执行 UIKit/SwiftUI，也不代表上述场景已通过。

## 聚合点 Liquid Glass（2026-10-28，待 iOS 26+ 真机执行）

实现：[NativeClusterMarkers.swift](../../ios/App/App/NativeClusterMarkers.swift)。个性化地图中的“聚合点液态玻璃效果”默认关闭，与原生玻璃按钮独立。启用后 SwiftUI 水滴玻璃层位于 WebView 之上、原生工具栏之下，不拦截触摸且不重复进入读屏树；全部聚合与转场由现有网页控制器驱动。协议 v2 用可见矩形片段裁切地图边缘和网页前景覆盖区，保留其余部分的玻璃；非模态筛选面板按实际表面矩形裁切，未覆盖部分继续显示玻璃，筛选产生的新聚合图沿用会话已确认的玻璃材质；模态浮层和暂时离页只隐藏原生层，已确认的聚合图不重新显示 PNG。数量显式使用当前地图主题的黑/白实色及反色细晕，SwiftUI 明暗与玻璃同步。旧版本、关闭聚合玻璃、减少透明度或桥接明确故障时继续使用 `src/img/union.png`。

| 操作 | 验证重点 |
| --- | --- |
| 冷启动，在地点密集区域拖动、惯性滑动和双指缩放 | 水滴玻璃实时取景；位置贴合底图，数量清晰；无图片与玻璃重影 |
| 连续缩放合并/拆分，在回弹或吸附中再次拖动、缩放 | 所有聚合点及退出残影同步移动、缩放、淡出；手势优先，无残影或数量错误 |
| 点击聚合展开，在最大缩放点击坐标重合的聚合 | 继续使用原有展开层级和成员列表；双指松开不会误触聚合 |
| 打开公告、搜索结果、展会入口、地点卡、列表和选点器；切换到其他页面再返回 | 网页控件保持遮挡优先级；关闭浮层和离页返回不会先出现 PNG 再切回玻璃；其他页面无玻璃残留 |
| 聚合点贴近地图四边、定位蓝点、已选中地点和新增地点；多个控件交叠覆盖同一聚合点 | 高优先级元素保持在前；可见片段仍是玻璃，完全覆盖时不露出 PNG |
| 新装或旧偏好仅有原生玻璃按钮开关，打开个性化地图；开启聚合玻璃后快速往返切换 | 聚合玻璃默认关闭且能独立开启，退出重开保留本机选择；旧关闭回执不能覆盖最新开启选择 |
| 浅色/深色地图、关闭聚合玻璃、减少透明度、减少动态效果、短暂掉帧 | 玻璃与数字主题跟随地图且数量清晰；关闭聚合玻璃或减少透明度时回退，短暂掉帧不改变已选材质 |
| 键盘出现/收起，前后台切换，页面重载 | 坐标换算正确；旧会话不恢复残影；短暂故障后能回到 PNG 并重新接管 |
| 大量聚合点、多次合并拆分 | 记录设备/系统、可见聚合数、跟手迟滞和帧率；系统玻璃实际性能尚未由浏览器测试验证 |

本地自动化覆盖桥接背压、过期回调、PNG 所有权与真实网页动画采样。Windows 环境不能执行 Xcode 编译、签名或系统玻璃渲染；安装测试前需要重新构建/同步 iOS 工程。

## 菜单形变、聚合读数与列表（2026-10-28）

收藏、随机美食与头像菜单复用右侧按钮组的一块常驻玻璃外壳：按最终面板宽度排版正文，再动画改变外壳的宽高与圆角，关闭时缩回右侧。工具栏与菜单分别合成玻璃，面板加载和内容更新不重建外壳；下滑时正文与玻璃一起移动。退场内容在动画结束后清除，快速重开时旧回调不能清掉新面板，新会话不保留旧账号内容。

聚合数字位于整个玻璃容器之外的前景层，不使用背景色或胶囊底衬；原生水滴玻璃在深浅模式下都叠加 60% 白色，数字统一为黑色，皮肤的固定数字色只影响普通图片标记。列表完全遮住聚合时，原生帧不再创建对应材质实例，同时保留 PNG 的隐藏状态；退出列表后再恢复玻璃，避免依赖空 mask 隐藏系统材质。真实浏览器回归使用实际 MapListMode，覆盖列表开关、旧帧晚到、重新打开与材质恢复。

移动端聚合命中区域直接处理手指轻触，在地图本轮手势结束后推进到真实拆分层级，不依赖 SDK 合成 click；同次触摸的 SDK 回调去重，拖动、取消和捏合不触发拆分。监听跟随可复用的标记 entry，单点与聚合互相转换后仍可正常操作；鼠标与单点继续使用原有 SDK 点击入口。

添加 / 修改地点表单复用地图的主题宿主，呈现前和布局时同步 UIKit 容器外观；SwiftUI 的整个呈现与不透明分组底色也跟随地图主题，避免深色地图上的表单被浅色系统面板洗白。

iOS 新手指引恢复“更多功能”：原生端显示上滑示意，实际展开后自动进入下一步；网页回退端指向“更多”按钮。完成记录版本不变，已看过的人可从“操作指引”入口重开。

安装新的 iOS 包后验证：

- 依次打开收藏、随机美食和头像菜单，再通过关闭钮、下滑、地图空白收起；确认从右侧按钮展开和缩回，关闭钮旁无小胶囊残影。
- 加载时快速关闭、重开与切换面板；收藏中打开地点卡、进入设置或退到后台后返回；确认没有旧正文、重复玻璃或失效触摸区域。
- 浅色/深色和复杂底图上查看不同位数的聚合数字；打开列表后确认玻璃和数字均不透出，关闭后不闪回 PNG。
- 使用固定数字色的皮肤，在地图静止时切换深色与浅色；原生水滴玻璃始终有白色叠层、数字始终黑色，没有数字背景胶囊。系统主题与地图主题相反时打开添加 / 修改地点，确认表单底色、导航栏和文字从第一帧起使用地图主题。
- 带灵动岛设备打开列表，顶部安全区显示列表背景，内容不进入状态栏；横竖屏与减弱动态效果下复查菜单和指引。

上述系统材质、SwiftUI 动画与真机安全区需要 iOS 26+ 的 Xcode 构建和设备/模拟器验收；Node 与浏览器替身测试不替代这些验证。
